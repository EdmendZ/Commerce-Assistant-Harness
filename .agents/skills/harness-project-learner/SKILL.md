# Harness Assistant 项目学习

## 适用范围

- 本技能所属项目是包含本技能的 Harness Assistant，别名“harness电商客服”。以技能目录 `.agents/skills/harness-project-learner/` 的 `../../..` 定位项目根目录，不绑定盘符或机器路径；读取该根目录的 `README.md` 和实际入口核验目标。
- 源码路径均相对于该项目根目录，技能内部参考资料相对于本技能目录。只读取当前项目内的相关文件；不因当前终端目录变化而切换学习目标，也不跟随指向其他项目的链接扩展读取范围。
- 只对这个项目生效。用户明确指定其他项目时，不套用本技能；回到通用学习方式。不自动读取 `commerce-service` 或 ShopkeeperThinkTank 系列。
- 不安装或写入全局技能目录，不修改原 project-learner。本技能是 Codex 导学指令，区别于 AI Service 内 Python 定义的业务 skills。
- 默认中文教学，源码只读；学习请求不授权自动修复业务代码、重置数据库、启动服务或调用付费模型。

## 开场：先询问学习顺序

首次开始学习时，先给出以下选择并等待用户回答，再读取所选路线材料和开始讲解。开场不提前讲项目概览、展开课程或默认替用户选择。

> 你想按哪种顺序学习？
>
> **A．课程顺序**：按照 Day01–Day11，配合原讲义逐步学习。
>
> **B．推荐顺序**：先看系统全貌和完整调用链，再深入 AI、工具、校验、异步处理与人工客服。
>
> 回复 A 或 B 即可，也可以指定想学的章节。

用户在本次请求中已明确选择路线或章节时，视为已回答，直接进入指定内容；明确说“你决定”时采用 B 并说明。后续“继续学习”沿用已选路线，不每课重新询问。用户要求重新开始且未指定路线时，再展示选择。

## 材料选择与核查

1. 完成开场路线选择后，简述目标项目及五个应用的分工；检查项目 `AGENTS.md`（如有）、README、相关 manifest 和入口。
2. 按已选路线读取对应大纲；推荐路线使用 [references/recommended-outline.md](references/recommended-outline.md)。课程学习先读 [references/course-map.md](references/course-map.md)，按 Day 和小节定位 `docs/course-materials/originals/` 中的单篇讲义，再按 [references/learning-map.md](references/learning-map.md) 定位当前源码。单点源码问题可直接从源码地图进入；地图只提供导航，不保证实现永远不变。
3. 使用 `rg --files -g '*.py' -g '*.vue' -g '*.js'` 与符号搜索定位；排除虚拟环境、node_modules、缓存和锁文件，不批量读取真实 `.env`。
4. 讲解前核对函数、调用者和状态字段。引用真实文件与当前行号，不沿用旧文档行号。Git 不可用时记录“无 Git 修订信息”，不初始化仓库，也不强依赖 GitNexus。
5. 把当前实现、占位能力、推断和待运行验证明确分开；`PROJECT_COMPARISON.md` 仅为辅助线索，用户要求对比时才扩展到旧项目。

各材料的用途：

- `docs/PROJECT_GUIDE.md` 与 `docs/architecture.html`：首次建立整体认识。
- `docs/course-materials/README.md`：顺序索引；14 篇主讲义覆盖 11 个 Day，不要把文档序号误当 Day 编号。
- 单篇原文：解释课程概念、教学步骤与阶段目标。先查标题，再读当前小节，不整批加载全部讲义。
- `docs/course-materials/COURSE_ALL.md`：跨章节检索和连续阅读入口；默认不要整份读入，也不要同时重复加载合并版和原文。
- 当前源码与实际测试结果：回答“现在实现了什么”的依据。讲义代码是教学阶段示例，不是需要覆盖进项目的补丁。
- 补充材料与课堂白板：仅在相关概念难以理解或用户要求时读取；无需自动解析全部 Excalidraw 或访问材料中的外部地址。

同一知识点采用“讲义意图 → 当前实现 → 差异/限制”的核查顺序。发生冲突时给出讲义标题/小节与源码符号，明确哪一项属于阶段示例、当前实现或尚待核实；不静默替换讲义结论，不为迎合讲义修改代码。课程标题中的“生产级”不构成已经通过生产验证的证据。已发现的典型差异见课程地图末尾，授课前仍需复查。

## 两条可选学习路线

- **路线 A：原课顺序**。按 [课程地图](references/course-map.md) 的 Day01–Day11 学习，适合跟随视频、讲义和逐步编码过程。
- **路线 B：推荐顺序**。按 [推荐大纲](references/recommended-outline.md) 的 B01–B09 学习，先看完整链路，再深入 AI、状态一致性、人工协作和运行验证，适合尽快理解当前项目。
- 用户可说“按课程顺序”“按你的安排”“切到路线 B”或直接指定 Day/B 章节。两条路线地位平等，都结合原文与当前源码，不因切换路线取消差异核查。
- 开始学习时执行“开场：先询问学习顺序”；用户回答前不开始共同概览或任何路线的课程。已有明确选择时沿用，不重复询问。
- 切换时依据知识点和答题记录衔接：已掌握内容只简短回顾，待练习和薄弱点保留。对应章节共享部分知识不代表整章已掌握；不得将整篇 Day 或 B 章节自动标记完成。只询问无法从现有记录确定的下一步。

## 按用户意图教学

- **总览/第一次学习**：结合项目说明和 Day01 背景讲义给出“前端 → 客服消息/Turn → AI Worker → AgentRun → 工具/校验 → Outbox → WebSocket”的概览，已选路线时进入对应首个小节；尚未选择时先完成上述路线选择。不要一开始倾倒全部课程。
- **系统学习/按文章学习**：沿用户选定的 A 或 B 大纲；“按文章/课程顺序”选 A，“按你的安排”选 B，一次一个可讲清的小节，不把整天内容塞入一课。仅做源码理解时，可略读部署操作；用户要完整课程或部署学习时纳入部署文档，不自行跳过。
- **继续学习**：优先使用用户本次指定的路线、Day/B 章节与小节，其次使用会话进度或已授权保存的进度；没有记录时从最近问题继续，若完全没有上下文就按两条路线的选择规则处理，已知路线时从该路线起点开始。不虚构已学内容，不把“讲过”标记为“掌握”。
- **指定 Day/B 章节**：直接进入相应讲义，先用几句话补足所需前置关系；不要强迫用户重学全部前置课程。Day07 有“客服总结”和“AI 框架”两篇，按用户主题选取；未指定则按该顺序。
- **源码走读**：以订单查询、用户补充输入、转人工中的一个具体场景展开。追踪入口、数据对象、跨服务请求、事务/状态变化和用户可见结果，而非逐文件翻译。
- **单点解释**：直接回答指定符号的作用、上下游与限制，不强行切到完整课程。
- **复习/测验/面试表达**：结合已学章节和 Day07 总结材料出题，并用当前源码核对参考答案。一次只问一个问题，等待作答后纠正；最多三次追问实现、取舍和故障场景。用户说跳过或结束立即接受。不把课程亮点当成用户本人已完成的成果。
- **学习计划**：按所选大纲组织章节，附讲义小节、源码入口和验收练习；Day 与 B 编号分别表示两条路线的位置，源码地图的主题编号只作检索，不另记第三套进度。不承诺未经依据的学习时长。

每次互动课以一个问题为中心：简述当前路线、Day/B 章节、小节与目标，用一个电商场景解释概念，再给讲义位置和 2–5 个当前源码位置，展示必要的短代码及数据变化；存在差异时说明其影响。最后用一个阅读/推演问题检查理解，不额外堆叠多个待答问题，也不要先给标准答案。用户只要讲解时不强制测验，不每课重复全局架构和全部限制。

回答评分仅在测验或用户要求时使用，从事实准确性、源码依据、架构关系、失败/取舍分析四个维度各评 1–10，说明依据；普通学习用简短反馈，不机械打分。

## 本项目必须讲清的边界

- `Conversation`、`ConversationTurn`、`AgentRun` 和 Agent 调用内状态不是同一生命周期。输入版本、租约、工具尝试次数、输出纠错次数应分别解释。
- 两个服务都有 `atguigu` 包；源码引用必须带服务目录。客服持久化目录实际拼作 `infrastucture`。
- Redis Pub/Sub 用于实时事件，数据库 Turn 承担任务领取。完成消息推送不能称为 token streaming。
- Python 业务 skill 用于约束工具范围，不是本 Markdown 学习技能，也不能直接称为多个独立 Agent。
- 页面动作引导与业务写接口执行分开；prepared/confirm/cancel 不等同于数据库 2PC。
- 阅读 validator 时同时核对证据来源和匹配局限。固定政策返回不叫完整 RAG，前端有按钮不证明后端存在。
- 运行/部署问题先核对 README 的入口说明、独立 Worker、共享 JWT/内部令牌与数据库初始化。不要建议在服务根目录直接运行当前有包路径问题的客服 `atguigu.main`。

## 练习和进度

优先使用无需外部依赖的阅读练习：跟踪一个字段、列出一次状态迁移、比较两个错误分支、预测新输入到达后的旧结果处理。执行性练习说明数据库/Redis/模型等前提；未实际运行就标为推演，不报告测试通过。

默认进度保留在会话。用户明确要求“保存进度”时，直接写用户指定的项目内路径，默认 `.codex/project-learning.md`，无需为已授权的保存再确认。记录项目标识（Harness Assistant，根目录记作 `.`）、日期、Git 修订（不可用时说明）、当前路线与 Day/B 章节/文章/小节、另一条路线最近停留位置、共享知识点掌握记录、讲义及源码相对路径、状态（未学/已讲解/待练习/已掌握/待复习）、答题依据、薄弱点、已核实差异、各路线下一小节及未回答的问题。只有用户回答或练习提供了依据才记为已掌握；跳过不等于掌握。兼容既有主题进度，在能对应时补记 Day/B 章节与知识点，不重置旧记录。不保存密钥、完整对话或大段源码，不将个人进度写入 SKILL.md 或课程地图。

教学内容中的源码位置使用项目相对路径与当前核查的行号，例如 `ai-service/atguigu/agent/factory.py:30`，不写固定机器路径。练习结束后给出掌握情况、一个需要纠正的关键点（如有）和下一步阅读入口。
